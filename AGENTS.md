# YBB-VIDEOZIP Project Notes

## Purpose

YBBvideozip is a desktop video compression tool being upgraded into a revenue-capable product:

- Free mode: compression remains available, but compression tasks can show ads.
- Pro mode: local activation removes ads.
- Current business goal: validate whether users accept the ad-supported/free path and a low-price Pro upgrade.
- Current Pro price target: 9.9 CNY.

This file is for future Codex sessions and project retrospectives. Keep it factual and update it when major architecture, release, payment, or operational decisions change.

## Repository Layout

The repository is moving toward platform-separated directories:

- `win64/`: Windows WinForms implementation, build scripts, docs, tests, and release package.
- `macos/`: macOS platform work area.
- `oss/YBBvideozipFFmpeg/`: files intended for OSS upload, including `ad-config.json`, examples, runtime manifests, and `pro.html`.
- `docs/`: cross-project or planning documentation.
- `secrets/`: local-only private files. This directory must stay ignored and must never be committed.

If the layout is still being reorganized, check `git status -sb` before editing and avoid touching unrelated moves/renames.

## Current Windows Product Behavior

- The app compresses video locally through FFmpeg.
- FFmpeg runtime is downloaded or resolved locally; it is not bundled as plain loose files in Git.
- Free users see an in-app ad during compression.
- Pro users enter a local license code and skip ads.
- The ad player uses the conservative WinForms/WMP implementation because WPF `ElementHost + MediaElement` caused layout, layering, and stability regressions.
- Ad video starts with sound enabled by default, with a visible sound toggle.
- The ad panel covers the queue area while active to avoid layer-order problems.

## OSS and Remote Config

Canonical OSS public paths:

- Pro page: `https://shenlouar.cn/YBBvideozipFFmpeg/pro.html`
- Runtime directory: `https://shenlouar.cn/YBBvideozipFFmpeg/`
- Ad config: `https://shenlouarwebsite.oss-cn-shanghai.aliyuncs.com/YBBvideozipFFmpeg/ad-config.json`

Operational rule:

- Upload `oss/YBBvideozipFFmpeg/ad-config.json` to OSS after ad URL or click URL changes.
- Upload `oss/YBBvideozipFFmpeg/pro.html` to OSS after Pro page copy changes.
- Keep ad video URLs stable and public. Avoid temporary signed OSS URLs in committed config.
- Do not commit STS tokens, `OSSAccessKeyId`, `security-token`, signed URLs, private keys, or payment credentials.

## Pro Page State

`pro.html` is currently a transitional page:

- Shows software and Pro information.
- Shows expected price: 9.9 CNY.
- Says Pro payment is not open yet.
- Does not show a payment QR code.
- Warns users that there is no user system, no license backup, and lost activation codes require repurchase.

Do not add payment QR codes until the payment backend exists.

## Licensing

The public repository must not contain license-generation secrets.

Current direction:

- The EXE contains only a public key.
- License codes are generated by signing payloads with a local private key.
- The local private key lives under `secrets/` and is intentionally ignored.
- The generation script reads the local private key and outputs a Pro code.

Before pushing public commits, check:

```powershell
rg -n "BEGIN PRIVATE KEY|PRIVATE KEY|<P>|<Q>|<DP>|<DQ>|<InverseQ>|<D>|OSSAccessKeyId|security-token|Signature=|STS\." . --glob "!dist/**" --glob "!.git/**" --glob "!secrets/**"
```

Expected result: no matches.

## Payment Direction

Preferred future payment flow:

- QR-code based payment.
- Alipay first, WeChat later if needed.
- Use an official merchant/API flow, not personal QR-code scraping or unofficial code-pay services.
- Since ECS is available and future services may also need it, ECS is the preferred backend path over Function Compute for this project.

Likely first backend shape:

- `pay.shenlouar.cn` or another API subdomain pointing to ECS.
- Nginx with HTTPS.
- Small backend service: Node.js or Python FastAPI.
- SQLite or another lightweight database for orders.
- Alipay pre-create / QR payment.
- Alipay async `notify_url` handler.
- License generation on confirmed payment.
- Optional email delivery.

Do not claim payment automation is complete until callback verification, order idempotency, amount verification, and license delivery have been tested.

## Release Checklist

Before creating a GitHub Release:

- `git status -sb` is understood.
- No unrelated user changes are staged.
- Version constant and EXE metadata are updated.
- Tests pass.
- Build passes.
- Package script passes.
- Private key and temporary OSS token scan returns no matches.
- Release notes mention all product-facing changes.
- The release zip is uploaded as a GitHub Release asset.

## Known Risk Areas

- WMP playback depends on Windows Media Player ActiveX availability and system playback support.
- FFmpeg is used for compression, not for the in-app ad video renderer.
- Current Pro license is offline and not machine-bound; users can share codes.
- Public source means any symmetric/shared-secret license scheme is unacceptable.
- Payment automation needs a real server-side callback handler; OSS-only static pages cannot confirm payment success.
- Do not rewrite broad UI layout without testing screenshots or at least layout math at default and minimum window sizes.
